# Piora 内置浏览器三点菜单实施计划

2026-11-22 · Windows 桌面端 · 交互与验收规范

目标是在 Piora 右侧浏览器的地址栏旁提供截图中的 11 项操作。用户可以一边聊天一边查找或打印当前网页，切换手机尺寸，把网页截图粘贴出去，找回昨天访问过的页面和下载的文件，并管理这个浏览器自己的登录资料。以现有 Electron `WebContentsView`、浏览器配置和 Agent 标签页机制为基础。

## 对照基线

- **Codex** 以用户截图和本机 Windows 版 `26.1117.4957.0` 为准。检查了安装包中的菜单组件、设备预设、查找、打印、截图命令以及历史和下载接口。菜单及子菜单由应用自己的 React 组件绘制，动作按对话、浏览器标签定位网页。历史查询和下载历史使用该运行时提供的接口。有关配置导入的结论来自界面流程与结果状态，未使用真实账户试导。公开指南另行确认了地址栏搜索、历史管理、下载位置和人机共享标签页。[OpenAI 浏览器指南](https://learn.chatgpt.com/docs/browser)
- **Piora** 以核对时的远端 `main`（`3d931edd`）为准。已有每个聊天的真实标签页、Agent 跟随、独立的 `persist:piora-browser`、导航按钮、站点缩放、Chrome 书签导入、下载事件、保存位置和网页凭据库。下载界面接收最近一次事件，前进后退使用当前标签的导航栈。核对期间还看到过本地列表草稿，实施时先检查是否已有相应改动合入。[浏览器面板](https://github.com/kexijiang/pi-desktop/blob/3d931edd4f197370e43ddb3ef3108104ec22f819/components/workspace/BrowserPanel.tsx) · [桌面浏览器管理器](https://github.com/kexijiang/pi-desktop/blob/3d931edd4f197370e43ddb3ef3108104ec22f819/desktop/src/browser-manager.ts) · [浏览器模式](https://github.com/kexijiang/pi-desktop/blob/3d931edd4f197370e43ddb3ef3108104ec22f819/docs/browser-modes.md)
- **首个交付平台**是 Windows x64 桌面内置浏览器。网页端及后台 Playwright 模式按各自实际能力显示入口，首版验收单列 Windows 桌面。下文的模块、数据表和批次均为实施建议。

### Chromium 的工具栏可以复用到哪一步

Chromium 源码本身包含完整浏览器的工具栏、三点菜单和下载按钮，这些代码位于 `chrome/browser/ui/views/toolbar`。Piora 通过 Electron 的 `WebContentsView` 嵌入网页。这个接口提供网页和导航对象，工具栏源码则依赖 Chromium 完整浏览器的窗口、配置与命令系统。直接嵌入那套工具栏需要引入并维护这些依赖，还要重新接上 Piora 的聊天侧栏、标签和 Agent。对于截图里的目标，保留当前网页视图，复用 Electron 的网页命令、下载事件和系统对话框，把菜单、记录和设置接到 Piora，涉及的改动范围更小。[Chromium 工具栏源码](https://chromium.googlesource.com/chromium/src/+/main/chrome/browser/ui/views/toolbar/) · [Electron WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view)

## 11 项菜单逐项设计

**菜单操作有两个范围。** 在标签 A 打开菜单，查找、打印、设备预览和截图都作用于 A。缩放沿用 A 所在站点的设置。历史、下载、资料导入和清理使用 Piora 当前内置浏览器配置，跨聊天、跨标签、跨重启可见。用户从设置返回时，原网页仍在原来的滚动位置。

下表按截图顺序排列。第二栏是从 Codex 确认的行为，第三、四栏给出 Piora 的实现与验收。

| 菜单 | Codex 的行为 | Piora 的实现 | 用户怎样验收 |
| --- | --- | --- | --- |
| 1. 在页面中查找 | 在目标网页上调用 `findInPage`，接收 `found-in-page`，关闭时清理选区。 | 在地址栏下显示查找条，提供上一个、下一个、当前序号、总数和关闭。网页获得焦点时支持 `Ctrl+F`、Enter、Shift+Enter、Esc。异步结果同时匹配标签 ID 和查询请求 ID。 | 页上有三个相同词时能逐个跳转并滚动到命中处。无结果显示 0。快速换词、切标签后计数正确，在聊天或编辑器中按快捷键仍交给原控件。 |
| 2. 打印 | 将打印命令交给当前网页的 `webContents.print()`。 | 从菜单或聚焦网页时的 `Ctrl+P` 调起 Windows 打印对话框。保留网页自己的打印样式。关联原标签处理关闭、取消和失败。 | 含专用打印样式的测试页打印到 PDF，核对页名和内容。取消后焦点回到原页。聊天区不会出现在打印件里。 |
| 3. 缩放 | 菜单内有减号、当前百分比、加号和复位，网页读取实际缩放值。 | 把现有站点缩放动作接入同一行。连续点按时菜单保持展开，在上下限禁用相应按钮。沿用现有按站点保存和同源标签同步的行为。 | 将 A 站调大，B 站仍显示自己的比例。重启后 A 站保留原值。在菜单复位后，网页和百分比同时回到 100%。 |
| 4. 设备工具栏 | 子菜单能显示或隐藏工具栏，可设为新标签默认开启。有响应式尺寸、手机/平板/笔记本预设、宽高输入、旋转和拖拽边缘。 | 每标签保存当前预设、逻辑宽高、方向和预览比例，新标签默认开关单独持久化。按逻辑尺寸渲染网页，在窄面板内等比展示。与 Agent 已使用的视口模拟统一调度。 | 用同一页面切桌面、手机、平板，检查实际 CSS 媒体查询及横竖屏变化。改变面板宽度后手动点击、Agent 点击和截图仍对准相同元素。尺寸预览的验收独立于真实手机兼容性。 |
| 5. 截取屏幕截图 | 桌面端执行当前网页的 `capturePage()`，再将图像写入系统剪贴板，并回报成功。 | 复用网页捕获和现有凭据保护，在主进程调用当前 Electron 的 `clipboard.write` 写入 PNG 图像。关闭菜单、等页面完成绘制后复制当前可见网页，显示“网页截图已复制”。 | 在画图或聊天草稿里粘贴，核对图像只包含该网页的可见部分。设备模式下捕获对应视口。快速切标签、页面销毁或受保护时不复制其他内容。 |
| 6. 导入 Cookie 和密码… | Windows 截图显示可以选择一份 Chrome 个人资料、勾选数据并点「导入」。弹窗说明了关闭来源浏览器及系统批准的要求。 | 目标是选定资料后点一次「导入」，需要时由用户完成系统授权。随后在 Piora 内置网页中延续可迁移的登录，并能用已保存的密码填表。Chrome 直导待实现。 | 准备两份不同的 Chrome 测试资料。选 A 后，在 Piora 打开 A 已登录的站点，再在另一站点填写仅 A 保存的测试密码。验证 B 独有的账号未被导入，重启后复核。分别记录登录和密码的结果。 |
| 7. 密码和自动填充 | 安装包中这个子菜单有**密码管理器**和**联系人信息**两个入口，按运行时能力显示。 | 密码入口直达浏览器设置中的「管理密码」，复用既有账户的创建、锁定、编辑和填写。联系人单列姓名、地址、电话和邮箱，提供增删改与用户选择后填入表单的交互。 | 菜单能定位既有账户。锁定后敏感信息不可见。另用一个地址表单选择联系人，可核对填入的字段，保存地址与保存网站密码各有独立入口。 |
| 8. 下载 | 菜单可达下载管理。工具栏能显示活动进度、完成或失败状态，列表提供暂停、继续、停止、打开文件、在文件夹中显示及移除记录。 | 复用 `will-download` 和 `DownloadItem`。活动对象由桌面主进程持有，多项记录写入持久存储。菜单打开下载设置页，工具栏下载图标打开锚定在按钮下的近期浮窗，两处使用同一份数据。 | 两项下载同时进行，暂停其中一项，另一项继续。可在资源管理器定位已完成文件。重启后仍能查，磁盘文件被移动或删除会显示对应状态。 |
| 9. 历史记录 | 菜单可达浏览历史。地址栏输入文字会匹配本浏览器访问过的页面，管理页可搜索、重开和删除。 | 从主框架已提交的导航建立跨标签访问记录。当前标签的前进、后退仍调用原有导航栈。地址栏提供匹配项，设置页支持按日期浏览和删除。 | 关闭原标签并重启，在地址栏输入中文标题或部分域名，能重新打开昨天访问的具体页面。删除后，管理页和地址栏都不再出现该条记录。 |
| 10. 清除浏览数据 | 有类别和时间范围选择。可见文案包括历史、Cookie 和站点数据、缓存、下载记录、表单数据、站点设置，以及最近一小时、一天、一周、四周、全部时间。 | 用同一份清除请求驱动各数据所有者，预览时说明范围与影响。浏览器分区、访问记录库、Cookie 恢复副本、联系人和站点权限分别处理。精确时间范围的限制见下文。 | 单独清历史后仍保持登录。只清下载记录后磁盘文件仍在。清站点数据后重启不会恢复旧 Cookie。用范围内外各一条数据验证边界。 |
| 11. 浏览器设置 | 从菜单直接进入当前内置浏览器的设置，历史、下载和资料管理有相应页面。 | 复用 Piora 已有设置路由和浏览器页。提供“历史记录、下载、密码与联系人、导入、隐私和站点、显示与设备”入口，沿用现有下载目录和每次询问选项。 | 从三点菜单直接进入指定设置，保存后返回原标签和滚动位置。菜单、地址栏、设置首页看到的记录和配置一致。 |

上述网页命令、导航、下载和剪贴板都有公开的 Electron 接口。Codex 用来查询整个浏览器配置的 `searchHistory`、`getDownloadHistory` 未列入 Piora 所用标准 Electron 的公开 Session 接口。历史和下载应有 Piora 自己可测试的数据来源。[网页命令](https://www.electronjs.org/docs/latest/api/web-contents) · [导航栈](https://www.electronjs.org/docs/latest/api/navigation-history) · [下载任务](https://www.electronjs.org/docs/latest/api/download-item) · [剪贴板](https://www.electronjs.org/docs/latest/api/clipboard) · [浏览器会话](https://www.electronjs.org/docs/latest/api/session)

## 面板、菜单和数据流

**菜单位置与原生网页层。** 三点按钮放在地址栏右侧，菜单按截图的分组排列，缩放控件可连续操作，子菜单支持鼠标和方向键。Piora 的原生网页显示在 React 界面之上，普通浮层设置再高的 CSS 层级也可能被网页盖住。先做一个 Windows 原型，在网页上打开缩放行和二级菜单。已有书签菜单使用 Electron 原生弹出菜单，可复用其定位与焦点处理经验。若要还原同一行内的加减按钮和复位，建议将交互菜单绘制在主窗口内、网页之上的独立受信任视图，仅覆盖菜单实际范围。关闭时销毁或隐藏该视图，焦点回到打开菜单的位置。原型通过条件是网页持续可见、菜单内点击不穿透、外部点击或 Esc 正常关闭，125% 和 150% Windows 显示缩放下定位正确。[Piora 书签菜单接入点](https://github.com/kexijiang/pi-desktop/blob/3d931edd4f197370e43ddb3ef3108104ec22f819/components/workspace/BrowserPanel.tsx#L445-L454) · [Electron 视图](https://www.electronjs.org/docs/latest/api/web-contents-view)

**动作作用域。** 查找、打印、设备模式和截图绑定打开菜单时的聊天及标签。主进程执行前复核标签仍属于该聊天、网页仍有效。切换对话时收起原菜单。历史、下载、联系人和清除数据绑定当前内置浏览器配置。用户打开配置管理页不会让网页或模型自动获得读取历史、剪贴板或密码的能力。下载和导入不因收起面板而丢失状态。

**模块归属。** React 管菜单、查询框和列表，preload 提供按动作定义的窄接口，桌面主进程持有网页、配置、凭据库及磁盘记录。沿用现有可信发送方校验。建议将新页面操作、视口协调、历史与下载存储、数据清除分到 `desktop/src/browser/`，由原有管理器接线。界面在 `components/workspace/` 的浏览器子组件和现有浏览器设置页组织。全局设置路由传入定位回调，操作成功后广播变更，避免菜单和设置各自缓存一份记录。[桌面浏览器与权限](https://github.com/kexijiang/pi-desktop/blob/3d931edd4f197370e43ddb3ef3108104ec22f819/desktop/src/browser-manager.ts#L488-L535) · [现有设置页](https://github.com/kexijiang/pi-desktop/blob/3d931edd4f197370e43ddb3ef3108104ec22f819/components/BrowserSettings.tsx)

| 界面请求 | 主进程契约 |
| --- | --- |
| 在某页查找、打印、截图、切设备尺寸 | 请求携带聊天、标签和动作所需参数。异步结果带回原标签与请求编号。网页关闭或切换后，迟到结果不写入新页面。 |
| 历史查询、删除、重新打开 | 查询传关键词、日期和游标。结果返回记录 ID、显示标题、可重开地址和时间。按 ID 删除。重新打开走现有导航入口。 |
| 下载快照、订阅和操作 | 打开列表时订阅事件并读取带版本的快照，按 ID 合并，只接受更新的状态。暂停、继续、取消、定位和移除均以已知任务 ID 为参数。 |
| 预览、执行清理或导入 | 预览和确认使用相同的范围及选项。执行时复核来源和能力，返回分项结果。窗口关闭后由主进程完成或明确取消，重新打开可核实结果。 |

### 历史和下载怎样跨重启保留

建议在桌面用户数据目录给内置浏览器建立独立 SQLite 库，沿用仓库已有的 `node:sqlite` 使用方式。主进程负责版本化迁移、事务写入与按游标分页。资料按浏览器配置隔离。首次升级从新的访问和下载开始记录，已有可验证的旧记录可一次性迁移。安装包升级、重复启动和崩溃恢复都纳入验收。[仓库内已有的 SQLite 用法](https://github.com/kexijiang/pi-desktop/blob/3d931edd4f197370e43ddb3ef3108104ec22f819/desktop/src/clipboard-database.ts)

| 记录 | 最少字段 | 写入与读取规则 |
| --- | --- | --- |
| 网页访问 | 访问 ID、配置、可重开的网址、标题、访问时间、可辨认的来源 | 监听主框架完成导航和同文档路由变化，合并一次导航里的重复事件，标题稍后到达时更新原条目。保留有意义的 `/#/chapters/1` 一类路由，跳过空白页、失败加载、子框架和含登录凭据的回调。按时间、标题、网址建索引。 |
| 下载 | 稳定任务 ID、配置、名称、保存路径、可显示来源、开始和结束时间、字节数、总大小、状态 | 开始时创建，普通进度节流写入，暂停、取消、完成、失败立即落盘。运行时用同一个 ID 找到活动 `DownloadItem`。重新启动后能查看过去记录。没有可恢复传输对象的任务显示“已中断”。 |

地址栏先在本地按标题、域名和网址匹配，将近期或多次访问的结果排在前面。同一网址的重复访问可在建议中合并，日期管理页保留各次访问。用户明确选择建议才跳转。直接提交网址或搜索词继续使用现有地址解析。旧请求晚返回时丢弃。中文输入法组词期间的 Enter 应完成选字。

下载沿用当前路径偏好、每次询问、同名避让和文件夹定位。列表操作传任务 ID，主进程从已保存的记录解析文件路径。进行中的“暂停／继续”依据任务能力启用。跨重启的“继续传输”须另验服务器支持、临时文件和实体是否仍匹配。能查到旧记录即可满足持久化验收，只有真正取得正确完整文件才算通过断点续传测试。清理下载记录与删除磁盘文件是两个独立动作。

### 设备模式和 Agent 如何共用一张网页

Codex 把设备预设的逻辑宽高与预览显示比例分别传给网页宿主。核对到的侧栏代码通过 Chromium 设备模拟接口覆盖宽高，该路径使用 `mobile: false` 和 `deviceScaleFactor: 1`。这解释了预设最直接的效果是让网页按指定宽度重新布局。

Piora 的 Agent 在标签隐藏时已使用设备尺寸覆盖，恢复可见时会清除覆盖。引入设备工具栏后，必须有一个地方统一计算网页的有效宽高、缩放和坐标映射。用户启用的设备预设保存为标签状态。Agent 临时需要的屏外视口在动作结束后恢复到该标签原有预设。切聊天、拖动侧栏、切换全屏、打开菜单或关闭设备栏时重新计算。页面缩放、设备逻辑宽高、为了塞进面板而做的预览缩放要分别保存。[Agent 视口切换实现](https://github.com/kexijiang/pi-desktop/blob/3d931edd4f197370e43ddb3ef3108104ec22f819/desktop/src/browser-agent-control.ts#L1068-L1136)

用带已知坐标按钮和桌面、手机两种布局的本地页面验证。分别记录页面观察到的视口宽高、媒体查询结果、人工与 Agent 实际命中的元素、粘贴出的截图尺寸。尺寸预设可先覆盖 Codex 界面已有的手机、平板、笔记本和响应式自定义档。只有实际实现并验证的触摸、像素比或浏览器标识才列入对应预设说明。

### 导入、密码与联系人

**Windows 上从 Chrome 一键导入登录状态和已保存密码，当前待实现。** 提交 `da17d1dd` 已验收个人资料选择、Chrome 历史导入、手选密码 CSV 以及 Piora 自有会话备份的恢复。Chrome 直导需要来源方支持的授权迁移通道。目前核对的 Electron 会话接口和 Google 公开的 Chrome 数据可携带类别中，尚未找到可由 Piora 在 Windows 上接收这两类数据的通道。[Electron 会话](https://www.electronjs.org/docs/latest/api/session) · [Google Chrome 可携带数据类别](https://developers.google.com/data-portability/schema-reference/chrome) · [Google 桌面密码导出说明](https://support.google.com/chrome/answer/13068232?co=GENIE.Platform%3DDesktop&hl=zh-Hans)

个人资料选项使用 Chromium 记录的本地名称和账号显示名称。筛选访问记录时使用所选资料中的 URL、标题和原访问时间。两个同名资料分别保留各自身份。[Chromium 个人资料属性](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/chrome/browser/profiles/profile_attributes_entry.cc) · [Chromium 访问记录结构](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/components/history/core/browser/visit_database.cc)

1. **先接回已有凭据库。** 密码管理器沿用 Piora 已有的锁定、解锁、按站点匹配、手动与自动账户、填写和加密备份。导入先做冲突预览，同站点同用户名默认跳过重复项，替换由用户选择。导入结果只显示站点和计数。联系人资料走独立的数据类型，复用系统加密，填写前让用户选中资料和目标表单。[Piora 凭据库设计](https://github.com/kexijiang/pi-desktop/blob/3d931edd4f197370e43ddb3ef3108104ec22f819/docs/credential-vault.md)
2. **建立来源能力表。** 第一条可交付路径是选择 Piora 已支持的加密备份，或用户从 Chrome、Edge 正式导出并选择的密码文件。解析和入库在本机完成，预览不显示密码，导入器不保留额外明文副本。浏览器书签导入保留原有入口和语义。[Google 官方导出说明](https://support.google.com/chrome/answer/13068232?hl=en) · [Microsoft 官方导出说明](https://support.microsoft.com/en-us/edge/export-passwords-in-microsoft-edge)
3. **Cookie 单独验证来源。** Codex 的 Windows 界面列出了来源受保护和部分导入失败的状态。Piora 需要先确认来源产品或站点是否提供适用于当前系统、由用户授权的登录迁移方式，然后用专用测试账户验证哪些会话确实能迁移。对支持来源提供选择、预览、导入、分项结果和重试。设备绑定或已失效的会话提示在 Piora 内登录。只有真实验过的来源才列为支持。密码文件导入成功不能计作 Chrome Cookie 直导完成。
4. **处理部分成功。** 对每个类别汇总成功、跳过和失败。先校验再写入，重试按来源和条目标识去重，保留导入前已有数据。验收覆盖同一配置重复导入、选择另一配置、取消、来源拒绝和重新启动。真实账户密码、Cookie 值、表单内容不进入日志、测试报告或 Agent 接口。

| 当前已核对的来源 | 现有密码导入方式 | 现有 Cookie 导入方式 |
| --- | --- | --- |
| Chrome 或 Edge 的本机个人资料 | 可在所选资料中打开其自带密码管理器，再选择该资料导出的 CSV。浏览记录可另行勾选，按该资料和站点导入，自动跳过重复访问。 | 外部浏览器的 Cookie 提示用户在 Piora 内重新登录。 |
| Piora 加密凭据备份 | 沿用既有解锁、备份口令和入库流程，在向导中说明既有备份的追加语义。 | 此备份的内容是凭据库。会话 Cookie 使用独立存储，向导按实际内容显示类别。 |

| Windows 上选择另一个浏览器的现有配置 | 探查该来源公开支持且用户授权的迁移能力，分浏览器版本登记结果。 | 只有来源允许迁移、用户选定范围、测试站能继续使用相应会话三项都通过，才交付该来源的 Cookie 直导。单独记录成功、来源不支持和需重新登录的站点。 |

### 清除数据的精度和恢复副本

先选择数据类型，再显示这些类型能执行的时间范围。对 Piora 管理且带时间戳的历史、下载、联系人和站点权限决定，可按所选区间处理。给旧权限记录迁移时保留“原始时间未知”，避免将其误判为刚刚创建。标准 Electron 的 `session.clearData` 支持数据类型及来源筛选，核对的接口没有起止时间。先交付能精确兑现的组合，Cookie、站点存储或缓存仅支持全时段时应在确认前显示具体能力。多个勾选项能力不同时，允许拆开执行。“最近一小时”不能触发扩大范围的清理。若要做到这些类别与 Codex 完全一致，应单列原生能力验证，以时间边界两侧数据的实测结果决定能否开放。[Electron 数据清理接口](https://www.electronjs.org/docs/latest/api/session#sescleardataoptions)

对“站点设置”逐类列清范围。首版可精确清理的是 Piora 已记录时间的权限决定。若要清除站点缩放等偏好，需要补充这些偏好的时间记录、迁移和相应的边界测试。

Piora 另有加密的会话 Cookie 恢复副本。清 Cookie 时要把清除与启动恢复、后台保存、退出刷新串行化，并按同一范围更新副本，避免重启把刚清除的登录态带回来。清除表单资料时明确列出是否包含联系人，独立密码库有自己的管理入口。跨数据源部分失败要列出已完成项和可重试项，刷新后核对实际结果。[会话 Cookie 存储](https://github.com/kexijiang/pi-desktop/blob/3d931edd4f197370e43ddb3ef3108104ec22f819/desktop/src/browser-cookie-store.ts) · [站点权限存储](https://github.com/kexijiang/pi-desktop/blob/3d931edd4f197370e43ddb3ef3108104ec22f819/desktop/src/browser-permissions.ts)

清理期间，进行中的下载继续出现在活动区，已移除的历史条目不能被迟到的进度或页面标题事件重新建回。Cookie 验收使用关闭自动登录的测试账户，再单独开启自动登录复测，从而区分“旧会话被恢复”和“凭据库发起了一次新登录”。
