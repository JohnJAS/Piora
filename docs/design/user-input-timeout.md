# 模型提问卡片倒计时

## 目标和交互

避免模型等待无人回答的问题而一直停在工具调用中。`piora_request_user_input` 默认等待整张卡片 60 秒；模型可通过 `timeoutSeconds` 为复杂问题选用 30～300 秒，最多三个问题共享同一截止时间。没有设置、非法或无限等待值不能取消服务端的超时保护。

卡片底部显示“60 秒后自动跳过”，每秒更新，最后 10 秒用提醒色；桌面和窄屏均显示。说明明确告知：到期关闭并继续，尚未提交的选择和文字不会作为回答。计时器不每秒打断屏幕阅读器。仍支持点击提交、Ctrl/Cmd+Enter、关闭按钮和 Escape；“跳过并继续”用于主动结束等待。

计时从服务端发出问题起算，输入和选择不会自动续期，刷新、切换任务、断线、重新打开任务不会增加时间。没有自动选择默认项，没有自动提交草稿。需要较长文本时由模型提前给予更长时间，最长五分钟。

## 结果语义

| 结束方式 | 工具结果 | 后续行为 |
| --- | --- | --- |
| 截止前提交 | `answers` | 使用用户明确提交的答案 |
| 主动跳过、取消或任务中止 | `cancelled: true` | 不推断用户选择 |
| 超时 | `cancelled: true, reason: "timeout"` | 明确告知没有答案或授权；继续现有指令支持的工作，说明假设，不立即重复提问 |

确实依赖回答或额外授权的步骤仍说明缺少的信息；继续不依赖该信息的工作。自动结束等待不等于保证所有业务都能在没有必要信息的情况下完成。超时结果作为普通工具结果进入会话历史。

## 实现边界

- 服务端为结构化问题分配请求 ID 和绝对 `expiresAt`，通过现有 SSE 发送并在重新连接时重放原截止时间。计时器独立于任何前端窗口。
- 收到回答时再次检查截止时间，防止事件循环延迟使过期回答被接收。提交、取消、超时和销毁共用一次性结算，清理定时器、AbortSignal 监听与待答请求。
- 结算广播同 ID 的 `close` 事件。前端仅关闭相同请求，不影响后续问题；本地也按绝对期限关闭，以应对 SSE 断线或后台节流，但不会伪造取消/回答发送给服务端。
- 现有扩展 `select/confirm/input/editor` 保留自己的等待策略，设置过超时时也会收到关闭事件；确认弹窗绝不因超时变为同意。
- 终端回退使用支持超时的选择/输入 API，多个问题共享总时限；避免进入不支持超时的终端多行编辑器。

## 验证范围

运行时验证默认/自定义期限、无客户端超时释放、正常提交、中止、重复与迟到回答、重连期限以及模型工具执行继续。浏览器验证实际卡片的倒计时、到期关闭、未提交内容不发送、正常提交/跳过、同 ID 关闭同步、旧关闭事件不影响新卡片、移动布局和双语显示。执行类型检查和 lint；不运行 Next.js 生产构建或本地发布打包。
