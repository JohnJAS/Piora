# 聊天命令处理与 UI 重设计

状态：已实现，未发布。本文规定交付行为、数据边界和验收条件；设计原型与实际实现的验证记录分开列出。

## 1. 问题与范围

原有输入同时承担自然语言、Pi 命令、扩展、模板和技能入口。命令处理分散在输入框、会话 Hook 和服务端，容易出现成功没有反馈、参数被当作问题、忙碌时命令被错误转入 steering，以及刷新丢失结果。

本次改造保留 Next.js 服务、进程内 AgentSessionWrapper、SessionMessageRouter、持久化命令日志、IndexedDB 恢复机制和现有聊天布局。不重写 Pi，不改变终端、Shell 或 Ctrl+K 应用命令。

目标是一次提交对应一个可追踪操作：输入有明确解释，运行有真实状态，结束有持久结果，失败有完整恢复路径。

## 2. 输入语义

| 输入 | 解释 | 后续行为 |
| --- | --- | --- |
| `/reload` | 重新加载资源 | 结果卡片显示扩展、技能、模板数量及警告，不调用模型 |
| `/reload 检查改动` | 无参命令 + 后续问题 | reload 成功后提问；失败保留并阻止问题 |
| `/session` | 读取统计 | 无需创建 AgentSession，显示结果 |
| `/copy` | 复制最近完成的助手正文 | 等待浏览器实际写入剪贴板确认 |
| `/name 新名称` | 命令参数 | 显示名称前后变化，不把名称另发给模型 |
| `/compact 保留接口约定` | 压缩指令 | 显示压缩结果和摘要 |
| `/扩展 参数` | SDK 扩展命令 | 原样交给 SDK 命令处理器，不作为普通 steering |
| `/模板 参数` | SDK 模板展开 | 遵循模板位置参数语义 |
| `/skill:名称 参数` | SDK 技能调用 | 保留 SDK 技能加载语义 |
| 未知或不可用命令 | 明确验证错误 | 保留输入，允许用户主动选择按普通文本发送 |

有参命令的尾部全部属于参数，不用标点或语言模型猜测参数和问题的边界。输入框提供独立“随后提问”字段；无参命令尾部问题与该字段同时非空时拒绝歧义输入。固定模板若不消费参数，不得静默丢弃尾部文本。

附件属于模型步骤。纯 reload、统计、复制、扩展操作没有后续问题时，不接受附件；模板、技能及带后续问题的操作允许附件。完整原文、附件和显式输入选项都先进入恢复存储。

## 3. 命令目录与权威边界

`chat-command-input` 为前后端共享解释器；`get_commands` 返回带版本的目录。描述符包含稳定 key、SDK 实际调用名称、来源、参数模式、忙碌策略及不可用原因。

目录冲突遵循内置优先、扩展优先于模板与技能，并输出诊断。客户端目录只做预览，服务端重新解析并验证动态目录版本。过期动态命令返回 409，不能悄悄执行另一个同名命令。显式普通文本模式必须禁止 SDK 再展开命令。

## 4. 提交与状态机

1. 输入框立即清空当前可见草稿，但暂缓删除持久草稿。
2. IndexedDB 保存原文、附件、输入选项和唯一 idempotency key；成功后才允许持久草稿清除。
3. 服务端 `submit_input` 校验身份、目录、输入语义，交给同一个 SessionMessageRouter。
4. 命令及后续问题作为一个 operation 持久化后才执行。重复请求返回同一提交结果，不靠文本去重。
5. 命令步骤成功后，后续问题进入原有队列；命令失败则问题标记 blocked，禁止继续发送。
6. 命令日志为结果权威；SSE 用于即时更新，HTTP 读取磁盘日志用于恢复和完成确认。

操作状态：accepted → queued / running → completed / failed / cancelled / interrupted。内部阶段包含 preparing、executing、waiting_input、waiting_client、model、settling。步骤分别保存开始、结束、运行 ID 和错误，不能用一个 HTTP 200 或 handler Promise 返回代表所有后代模型工作完成。

刷新不得重放已开始的命令。服务进程重启后，无法证明完成的运行标记 interrupted，等待用户恢复或重试。新重试使用新 key 并关联原恢复链；内容相同的独立发送仍是两次操作。

## 5. 忙碌、扩展与取消

reload、重命名、压缩等改变会话状态的内置操作等当前运行结束；只读统计、复制可直接读取；扩展命令通过 SDK prompt 命令入口即时执行。模板与技能本质上可能触发模型，必须遵守模型运行和队列边界。

忙碌时输入区提供来源相关的交付选择：扩展可选立即执行或当前任务结束后执行；模板、技能默认结束后执行，也可显式选择干预或 SDK follow-up。参数先由 SDK 展开，在 SDK 公共 Agent 入队边界为确切的用户消息附加材料，不靠文本匹配找队列项。复用现有模型运行的命令不获得中止整个父任务的权限；独立启动的模型步骤才可按自己的运行 ID 取消。

每个扩展操作以 AsyncLocalStorage 隔离 commandId、阶段、错误及尚未 await 的 SDK 子工作。扩展错误事件只归属于自己的操作；子模型工作结束及 SDK idle 后才结算。扩展独立启动模型时建立 PromptRun，已有模型运行时不得抢占或清理其身份。

取消能力必须真实：排队步骤可取消；模型步骤可中止；剪贴板等待可撤销；不可中断的原生 handler 不显示虚假停止成功。旧运行事件不能恢复新运行的 streaming 状态。

## 6. 结果 UI

### 输入区

- 保留现有输入框、模型选择与附件功能，在其上增加来源标签、命令 chip、参数提示和目录加载错误。
- `/` 菜单在忙碌时仍列出命令，明确标记立即执行或等待，不通过隐藏命令回避状态。
- 两步提交预览“执行命令 → 随后提问”，发送按钮使用“执行”或“执行并提问”，避免与普通消息混淆。
- Enter、方向键、Escape 和中文输入法组合输入不得冲突。恢复操作不得覆盖用户后来输入的新草稿。

### 时间线

- 命令不是临时 toast，也不是空助手消息；结果卡片插在实际发送位置，使用独立 row key，不伪造 SDK entryId。
- 卡片包含命令名、来源、状态、结果摘要、警告及耗时；详细信息展开显示原始输入和来源。
- 两步操作分别显示命令结果与问题状态。命令失败后可编辑问题或恢复全部输入，不自动再执行命令。
- 支持真实适用的重试、再次执行、取消、复制确认、统计入口；操作失败留在卡片内显示，不吞掉错误。
- 同时兼容传统与轻量过程展示，命令卡片不被工具过程折叠吞掉；窄屏换行，采用应用现有主题变量。

## 7. SSE、恢复与隐私

命令 SSE 使用独立 scope，不为读取结果启动 AgentSession。先订阅并缓冲，再建立快照游标，回放游标后的事件。快照提供最近结果及所有非终态操作；旧结果按需分页。断网、回到前台及定时 reconciliation 用磁盘日志补齐。

前端按 commandId 合并，按 idempotency key 替换本地占位，终态不被迟到的 accepted 回执覆盖。本地恢复与服务器快照无论何种到达顺序都只能显示一张卡片。目录缺失时仍应显示可恢复原文，不能因为解析失败隐藏用户内容。

剪贴板正文只保留在服务端短期内存，日志仅记录请求 ID、字符数、有效期。浏览器点击复制后读取正文，实际 clipboard.writeText 成功才发送精确确认；60 秒未确认失败。刷新不隐式复制，不把正文带进 SSE 或通知。

## 12. 接口与兼容

`POST /api/agent/[id]` 使用 `type: "submit_input"`，必要字段为 `message` 和唯一 `idempotencyKey`；可选 `inputMode: "text"`、`commandKey`、`catalogRevision`、`afterPrompt`、`delivery`、`images`、`materials` 和 `localFiles`。原生文件只传名称、路径及字节数，不把文件正文变成命令参数。

成功保持 `{ success: true, data: receipt }` 契约。receipt 包含 accepted、commandId、sessionId、当前状态及可用的运行/队列信息，只代表持久接收，不代表执行完成。动态目录过期返回 409，超限返回 413，语义错误返回 400。

`GET /api/agent/[id]/events?scope=commands` 提供 command_snapshot 与逐项状态事件，包含游标和 revision。`GET /api/sessions/[id]/submissions?view=operations&offset=…` 分页读取磁盘结果；`commandId=…` 取回原文、显式选项及附件。

复制分为 read_command_client_action 与 confirm_command_client_action，均校验 commandId、requestId、有效期及状态；实际写入成功才发送 success: true。旧 prompt、steer、follow_up、Ctrl+K 和终端入口保留，新输入框不依赖旧的内存命令回显。没有改变 Pi 依赖、工具权限或已发布版本号。
