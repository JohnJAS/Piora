# Piora AI 娘主题设计稿

日期：2026-10-30。状态：20 款主题已接入 Piora「设置 → 外观 → 主题与配色 → 角色主题」，工作区实现完成；未提交、推送或发布。

直接打开 [index.html](index.html) 即可离线预览。点击主题卡片，会同时切换背景、界面底色、文字与强调色；支持按角色、明暗筛选，以及原画/聊天效果切换。本页聊天界面仍是设计模拟；应用内最终配色另做了文字对比度调整。

## 设计判断

这套主题最值得保留的是角色辨识度和陪伴感。主题的差异应同时体现在角色轮廓、场景、色温与界面配色上。11 位 AI 角色依据用户指定的 [JohnJAS/ai-chan-sheets](https://github.com/JohnJAS/ai-chan-sheets) 补全设定图生成；Hello Kitty 拟人是单独的一组。

人设参考到位后，GPT 从初期自由设计的银发薄荷角色改为白龙娘；Claude 从短发文艺角色改为长橘发、菊纹与黑白橙长裙。鲸鱼娘保留侧鳍、呆毛、鲸尾和蓝白女仆裙。其余角色也保留各自关键轮廓，不把所有人都画成同一套换色服装。

原先四组各三款，加上项目其余八组各一款，共 12 位角色、20 款主题。每张单独调用内置 `image_gen` 生成；使用设定图作参考，没有把原图直接当背景。所有终稿都已保存，早期自由设计稿未列入本套终稿。

## 一键主题应包含什么

1. 背景原画与缩略图：原画不烘焙按钮、文字或界面，后续可以复用和裁切。
2. 色彩：底色、面板色、文字色、强调色；选中、边框、代码块可在接入时由基色推导。
3. 背景遮罩与面板遮罩：按明暗分别保存，保留手动调节入口。
4. 角色焦点：建议约在画面右侧 80% / 高度 34%，窄窗口需要单独验证裁切。
5. 来源与署名：随主题资源记录，不依赖外链图片运行时加载。

一键切换只改变外观。模型选择、系统提示词、人格、工具权限不应随主题变化。角色装饰也不应覆盖输入框、代码、审批按钮或阻挡鼠标交互。第一版建议静态图，动效与桌宠另外设计，避免把一键外观和运行行为混在一起。

## 接入现有 Piora 的位置

- `components/AppearanceLooks.tsx` 已有组合外观结构，可绑定主题、背景和各面板遮罩。
- `lib/theme-preferences.ts` / `hooks/useTheme.ts` 管理配色与持久化。
- `lib/backgrounds.ts`、`hooks/useBackground.ts`、背景 manifest 管理本地背景和遮罩。
- `lib/character-themes.ts` 保存 20 款角色主题目录，`lib/theme-preferences.ts` 已扩展主题类型与首次绘制恢复；无需改变 Dream Skin 的独立样式包。

角色目录与设置页分离，设置页提供角色分组与缩略图。切换时保留此前的自定义背景和配色，允许恢复原来的外观。首次绘制读取持久化主题；图片加载失败时保留该主题的底色与渐变回退。

正式实现见 `lib/character-themes.ts`、`components/CharacterThemeLooks.tsx` 与 `app/character-themes.css`。运行时只加载 `public/themes/character-backgrounds/` 下的 WebP；支持角色筛选、一键配色与背景、持久化恢复和恢复切换前的自定义图片。自动化已覆盖所有 20 款切换、重载、背景恢复与窄窗口；完整桌面安装包和真实多工作区布局尚未验收。

## 阅读性与性能

原画尽量把角色集中在右侧，左侧降低细节，但并非每张都有完全空白的 62% 区域，长裙、翅膀、光影仍可能进入中部。最终效果应依赖面板背景保证文字阅读，不能仅靠把整张图模糊处理。预览中的消息卡片使用约 92% 面板底色，输入框更实；角色区保留原画。滑块调节侧栏遮罩用于观察氛围强度，不代表正式应用的最终数值。

PNG 原画保留原始分辨率；WebP 只做格式与压缩转换，不重新绘制或改变构图。20 张 WebP 合计约 4 MB，应用按需加载；PNG 原画约 43 MB，作为设计源文件保存于本目录，不放入应用 public 资源。预览卡片采用懒加载。

## 文件与复现

- `index.html` / `preview.css` / `preview.js`：无需构建、无需联网的设计预览。
- `assets/*.webp`：20 张轻量预览资源。
- `originals/*.png`：20 张模型原始输出。
- `manifest.json`：每张的完整最终提示词、参考图片 URL、参考提交、PNG 校验值、配色与建议遮罩。
- `themes.js`：供离线页面读取的主题数据，内容来自 manifest，省略长提示词。
- `verification.json`：完成后的浏览器与资源检查记录。

生成方式为 Codex 内置 `image_gen`，没有使用外部 API、CLI 模型或项目脚本中的模型。参考输入为项目 `设定图/*/便于查看/*三视图*` 的 JPG；使用前逐张检查，模型仅将其用于身份、服装和饰品参考，输出单角色场景图。Kitty 的两款变体使用本轮生成的首图保持身份一致。
