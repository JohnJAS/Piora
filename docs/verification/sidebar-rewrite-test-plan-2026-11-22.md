## 执行顺序与复测证据

1. 先把 R1–R4 以及 L05 的时序写成会失败的行为测试。浏览器夹具按请求 ID 手工释放响应，断言原稿、标签、DOM 和最终状态。对这些测试，任意延时后“看起来没报错”不能替代顺序与内容断言。
2. 补 R5、R7 与 S10 的路由测试，使用独立 Agent 目录、真实 `SessionManager` 和合成历史。每条用例核对父 ID、子 ID、命令 ID、落盘文件和请求状态。只在主会话主动写入时允许其历史字节变化。
3. 左栏复用项目分页、群组、运行状态套件。右栏修正解析器，加入动态标签、跨会话和输入失败回归。随后跑独立 Electron 场景。现有 `worktree-chat-layout`、`subagents`、`plan-goal` 可覆盖交界处。建议在现有 harness 增加专门的侧聊场景，用本地脚本模型控制首条回复和并发。专门场景目前尚未注册。
4. 最后做 A02、A04 和 A05。保存操作录屏或截图、实际 ID、请求顺序、磁盘前后状态和故障注入点。报告分别标记已通过、已复现、未运行和失败，复测保留原有断言。对这版优先验收的结果是完整输入可恢复、父会话隔离、临时关闭确认有效，以及左侧与磁盘状态能收敛。
