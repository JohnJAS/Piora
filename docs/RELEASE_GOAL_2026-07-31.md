# Piora 今晚交付目标与进度（2026-07-31）

> 本文是本轮开发的唯一交付基线。范围、验收证据、风险和进度都在这里持续更新；如果实现与本文冲突，以“产品不变量”和最新决策记录为准。

## 1. 最终目标

今晚完成一个可公开发布的 Piora 首个版本：它仍然是 **Pi TUI 的桌面 GUI 封装**，不改写 Pi 的核心能力，只把桌面端的文件工作流和视觉体验提升到接近 Codex 桌面应用的完成度，并把完整源码、开源治理材料和可复现的验证流程发布到 GitHub。

公开仓库：[`kexijiang/piora`](https://github.com/kexijiang/piora)。仓库已经创建为 Public，
本地 `origin` 已指向该仓库；远程 `main` 与公开 CI 已投入使用，当前工作树的最终提交、最新 CI 与 Release 仍以本文后续状态为准。

## 2. 产品不变量

以下内容不是可选项，任何实现都不得破坏：

1. 主页面的用户消息、助手回复、Markdown、工具调用和 Process 展示格式保持不变。
2. 左侧下方文件树保留，仍是项目文件的主要入口。
3. Pi 的会话格式、运行时、工具、skills、extensions、packages 和配置目录继续作为唯一能力来源。
4. Piora 不增加自有的 SubAgent 产品模型，不复制或包裹 Pi 已经提供的扩展能力。
5. 主题只是宿主控制的视觉层：不注入其他应用，不使用 CDP，不执行主题 JS，不加载远程 CSS 或远程图片。
6. 默认不遥测；凭据、会话、项目文件和用户背景图均保留在本机，除 Pi/用户主动发起的请求外不新增后台网络行为。
7. 文件写入只能发生在已授权项目根目录内；只读会话引用不得被提升为写权限。
8. 视觉精修对齐 Codex 的克制层级与操作清晰度，但不复制其品牌、图标、专有素材或页面结构；圆角、阴影和装饰必须服从信息层级。
9. 桌宠/陪伴界面必须可选、可完全关闭且不遮挡聊天、输入框、编辑器或文件树；它只呈现已有任务状态和便捷动作，不成为新的 Agent/SubAgent。
10. “Codex 桌宠包”兼容只允许导入经过校验的声明式清单与本地视觉资源，不执行包内 JavaScript、HTML、CDP、安装脚本或远程资源。

- 不重写 Pi AgentSession、模型、工具或会话协议。
- 不新增任务市场、积分、人格卡、快捷卖点卡、内置 SubAgent 编排等产品层。
- 不复刻参考图里的明星、动漫、Codex/OpenAI Logo、字体或其他受限素材。
- 不允许主题包运行任意 HTML、JavaScript、npm install script 或联网资源。
- 不允许桌宠导入包绕过同一安全边界，不提供任意脚本插件、CDP 注入或后台自主执行能力。
- 不让桌宠成为默认强占注意力的营销入口；核心聊天、文件树和编辑器始终优先。
- 不为了首发加入自动更新、遥测、账号体系或云同步。

## 5. Codex 对齐准则

对齐的是工作流质量，而不是复制品牌或页面：

| 体验 | Piora 决策 |
| --- | --- |
| 文件在对话旁直接编辑 | 对齐，放在现有右侧文件面板 |
| 保存状态与磁盘冲突 | 对齐，使用显式 dirty、409 和三路决策 |
| 标签式文件工作区 | 保留并加强脏状态/关闭保护 |
| 左侧项目文件树 | 保留 Piora 现有位置与行为 |
| 对话回复格式 | 完全保留 Piora/Pi 现有格式 |
| 主题与背景 | 做安全、轻量、可关闭的本地视觉层 |
| 圆角与视觉层级 | 对齐克制、清晰、成组的操作体验，不复制 Codex 品牌或逐像素外观 |
| 相关设置组织 | 按实际工作流就近分组，减少重复入口和菜单跳转 |
| 桌宠/陪伴界面 | 作为可关闭的状态与快捷短语表面，不遮挡核心工作区、不建立新 Agent |
| Codex 桌宠包导入 | 只兼容可验证的声明式数据与本地资源；未知格式先建兼容矩阵，不承诺任意包直接执行 |
| Agent/扩展能力 | 服从 Pi 原生扩展机制，不复制 Codex 概念 |
