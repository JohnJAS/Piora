# 本地凭据库

内置浏览器默认记住成功登录的账户并允许自动登录，不需要创建或解锁手动凭据库。在设置的“数据与诊断”中可管理网页登录账户；旧版主密码凭据库的存储与填写继续兼容，但该设置页不展示旧版创建、解锁和备份界面。

旧版界面通过至少 12 位主密码创建凭据库，添加登录页 URL、用户名、密码、名称、分组及备注。解锁有效期为 10 分钟，重启后保持锁定。界面默认遮盖用户名与密码，编辑已有账户时密码留空表示保留。

数据独立保存于 Electron userData 的 `credential-vault.enc`，由 Electron `safeStorage` 系统加密保护（Windows 为 DPAPI）。不提供明文导出、服务器 API 或模型工具；系统加密不可用或 Linux 使用 `basic_text` 后端时拒绝启用。主密码用于解锁验证及备份验证，本地文件由系统账户密钥保护。忘记主密码不能通过界面恢复。

导出需要重新输入当前主密码，再选择文件。备份采用 scrypt 派生密钥及 AES-256-GCM 加密；导入需要先解锁凭据库，再输入备份导出时的密码。导入全部验证成功后追加条目，不覆盖原条目；重名/重复站点会形成多个候选，需要用户选择。普通会话/设置导出不包含此独立文件。

## 填写

手动凭据库的自动填写默认关闭；开启后检查唯一匹配项。关闭时可在浏览器登录菜单中选择账户，或在凭据库点击「填入当前浏览器」。默认记住的网页登录账户独立启用自动登录。内置浏览器在页面加载和动态登录表单出现时主动检查；后台 Playwright 浏览器在智能体登录交接时恢复，其他应用输入框不接入。

匹配采用精确 HTTPS origin 与路径，不支持通配域名；拒绝明文 HTTP、IP 地址、带账户信息或 Punycode 的域名。查询串不参与匹配。不再根据 password、security、verify 等路径关键词拒绝登录，改为检查字段用途与操作结构。支持标准同源 POST 表单、无 form 的 JS 登录、明确用户名字段旁的额外输入框、用户名后密码的分步登录和同源 iframe。跨源 iframe、原生 GET 表单、验证码、新密码、支付和无法唯一识别的表单不自动填写。

未开启账户自动登录时，不自动点击登录或提交表单。每次填写前隔离页面截图、执行脚本及 CDP 读取，并丢弃此前未返回的读取结果。完成登录后，如果最近一次填写的文档已经被完整导航替换，直接恢复当前页面，保留其历史和 sessionStorage；同文档 SPA 登录仍替换标签页以销毁接触过密码的执行环境，这类站点的内存和 sessionStorage 可能丢失。用户可关闭受保护页面来放弃登录。审计仅记录条目名称、站点与时间，不记录密码或表单内容。

系统加密保护静态文件，不构成对同一系统用户的任意本机程序、已授权全权限 Shell 或目标网站本身的隔离。网站会接收到填写的凭据；请仅为自己信任的站点保存账户。自动填写不向会话历史、模型请求或应用日志发送用户名和密码。

## 验证边界

- 存储测试使用注入的 AES 加密夹具，验证磁盘无明文、错误密码、篡改备份、原子导入、匹配与失败保留原数据。
- IPC/浏览器管理器测试使用 Electron 夹具，验证不可信发送方拒绝和迟到读取丢弃。
- 浏览器测试在真实 Chromium/Edge 中验证登录表单填写、不会提交及危险表单拒绝。
- Windows 原生测试使用无窗口 Electron 和真实 `safeStorage`，验证加密落盘、重建实例解锁与读取；其他平台跳过此项。
- 原生保存/打开对话框、真实网站登录及发布安装包仍需单独实机验收。


## 默认记住网页登录账户

内置浏览器默认在可信用户点击或键盘提交受支持的 HTTPS 登录表单后，将账户暂存在桌面主进程内存中。分步登录的用户名最多暂存两分钟，仅在同源密码步骤使用，并记住实际观察过的两个登录路径。程序调用 requestSubmit 本身不触发账户保存。只有观察到登录成功标记（退出登录按钮或用户菜单）、登录/验证表单消失且没有失败信号时才加密落盘；失败、超时和关闭页面丢弃暂存值。不需要创建或解锁手动凭据库，也没有保存账户菜单或逐站点确认步骤。

这些账户保存在 `credential-vault.enc.browser`，使用系统加密，重启后可用于自动登录。设置 → 数据中的“自动保存网页登录账户并自动登录”默认开启，随时可关闭；已记住账户可单独停用或删除，删除后不再自动记住该登录页。页面脚本和模型无法调用捕获 IPC，密码不进入聊天、模型请求、日志或设置快照。系统加密不可用时禁用保存，不降级到明文。

原有手动凭据库仍是可选的独立功能，保留主密码、解锁和备份规则；不会因为新增默认功能而解锁或覆盖原有条目。原有账户的显式停用优先于自动记住账户。

自动登录恢复支持桌面内置及后台浏览器；后台浏览器复用已保存账户，不具备首次人工输入入口。可识别登录表单稳定约 1.5 秒后开始尝试；没有表单的 SSO 跳转继续等待，总预算 60 秒。用户名和密码步骤各最多提交一次；失败后同一认证 origin 冷却五分钟，确认成功后释放冷却。同源标签排队共享恢复结果，后续标签只重新请求登录页以复用 Cookie，不重复业务提交。验证码与不支持的表单仍交还用户。缺少成功标记的网站不自动保存。

填写由桌面主进程执行，后台连接应用自己 profile 的本地调试端点。纯 Web 模式只尝试网站自己的 SSO，不访问桌面凭据库。用户直接访问站点、动态登录表单出现时也会恢复已有账户。浏览器状态栏显示保存中、已保存、需要验证码、表单不支持、冷却和未确认成功等结果，不显示凭据值。

## 网站权限

HTTPS 主框架在可见的内置浏览器标签中首次申请受支持权限时，显示原生允许/拒绝对话框，可记住选择。决策按完整 origin（含端口）保存；麦克风和摄像头分别授权。登录菜单中的“重置此站点的网站权限”清除之后请求的决策，已运行的媒体流需刷新或关闭页面停止。隐藏页、子框架和未配套设备选择流程的权限不会弹出新授权。屏幕捕获、USB 等仍需各自的实现，不因本次改动而开放。

## 页面脚本

内置浏览器的 `evaluate` 不再按登录路径、密码框、支付或安全文字拒绝执行，也没有相关开关。仍检查当前标签与文档身份；保存和填写凭据期间的页面读取隔离、取消与超时处理保持有效。
